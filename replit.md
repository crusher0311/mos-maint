# MOS Maintenance MVP

## Overview
MOS Maintenance MVP is an AI-enhanced automotive maintenance management system built with Next.js. It aims to optimize operations for auto shops by providing tools for managing vehicle maintenance recommendations, customer data, and multi-shop user management. The system seeks to boost operational efficiency and customer engagement through an intuitive dashboard, various integrations, and AI-powered insights, with the goal of becoming a leading platform for automotive service management.

## System Architecture
The application is built using Next.js 14.2.5, React 18, Next.js API Routes, and Tailwind CSS, primarily with TypeScript. It employs a dual-database strategy with Supabase PostgreSQL for core relational data, CRM, and communications, and MongoDB Atlas for caching and legacy features.

**UI/UX Decisions:**
The UI features a modern SaaS aesthetic with a dark sidebar, light content areas, and card-based layouts accented with blue. It includes a unified integrations page, tabbed vehicle detail views, visual data source badges, and dedicated UIs for "My Oil Sticker" and "Quick Sticker" with customization and rapid printing. A visual designer with drag-and-drop functionality is provided for keytag printing. Vehicle Health Intelligence (VHI) pages display OEM logos and dynamic vehicle titles, and VIN tooltips offer service-relevant specifications.

**Technical Implementations:**
*   **Data Management**: Core CRM and communication data reside in Supabase PostgreSQL, accessed via Drizzle ORM. MongoDB Atlas is used for caching.
*   **Integration Mechanisms**: A modular integration layer supports various shop management systems (e.g., Tekmetric, Protractor, Shop-Ware) using adapter and facade patterns. Tekmetric inspection data is fetched via internal API at `/api/shop/{tekmetricShopId}/repair-orders/{roId}/inspections` (not the public v1 API) using `x-auth-token` (browser session token, NOT OAuth). Inspections use `inspectionTasks[].tasks[].inspectionRating.code` with values: `CHCKD` (green), `MAYRQRATTN` (yellow), `RQRSATTN` (red), `NA` (skip). Inspection results are cached on `tekmetric_work_orders` documents in MongoDB.
*   **Tekmetric x-auth-token Storage**: The Detect Dog extension captures `x-auth-token` from Tekmetric browser sessions and relays it to `POST /api/extension/auth-token` (debounced per-shop, every 30 min). Stored on shop docs at `tekmetric.xAuthToken`. All sync paths (cron, incremental, backfill) use stored tokens via `getRepairOrderInspectionsWithXAuth()` to automatically pull inspection results server-side. Extension also directly relays inspection data to `POST /api/extension/inspections` as a secondary ingestion path.
*   **Authentication & Authorization**: Role-based access is implemented with bcrypt hashing and token-based authentication.
*   **Billing & Licensing**: Stripe integration handles VIN-based billing, supports modular feature flags, and manages various plan tiers.
*   **Admin & Monitoring**: The system includes admin audit logging, unified API usage monitoring, a support ticketing system, a platform observability page, and a Client Health Score dashboard.
*   **Client Health Dashboard**: A weighted health score (0-100) per shop based on billing status (25%), integration health (25%), activity recency (25%), feature adoption (15%), and support ticket status (10%). Risk levels: healthy (75+), monitor (50-74), at-risk (25-49), critical (0-24). Includes open ticket flags per shop. Located at `/platform-admin/client-health`.
*   **Notification System**: Email notifications are handled via Resend API, complemented by in-app notifications.
*   **AI Support Chatbot**: An OpenAI-powered floating chat widget provides instant answers and knowledge base retrieval.
*   **Sticker & Keytag Generation**: QR codes are generated via HoverCode API, and stickers/keytags are rendered using `node-canvas` for efficient printing with Dymo label printer support.
*   **Chrome Extensions**: Extensions enhance functionality for Shop-Ware (context detection, repair order items), AutoFlow (DVI context detection with multi-integration shop resolution), and "Detect Dog" (maintenance recommendations, job history, AI customer concern assistant). AutoFlow shops can have a separate write integration (e.g., Protractor) for pushing data, while reading DVI context from AutoFlow pages.
*   **API Sniffer (Dev Tools)**: Platform-admin-only feature in Detect Dog extension for capturing and analyzing API traffic from Tekmetric, AutoFlow, and Shop-Ware. Intercepts fetch/XHR at page level and webRequest at network level. Captures are stored in `chrome.storage.local` (max 500 entries, 10KB body limit), categorized automatically (DVI, estimates, scheduling, etc.), and exportable as JSON. All sniffer endpoints enforce `platform_admin` role check. Auth tokens and cookies are redacted from captured headers. Files: `sniffer.js`, `sniffer.html`, interceptor.js sniffer mode, background.js sniffer handlers. Accessed via Settings → Developer Tools → API Sniffer.
*   **AI & Recommendations**: The system provides AI-powered maintenance recommendations, job search, smart job autocomplete, and a common failures advisor.
*   **Estimate Assist & Audit**: A comprehensive estimate building and auditing system consisting of:
    *   **Job Knowledge Base** (`lib/estimate-assist/job-knowledge-base.ts`): ~200 automotive repair jobs across 13 categories (Brakes, Engine, Fluids, Suspension, Electrical, HVAC, Tires, Drivetrain, Exhaust, Cooling, Diagnostic, Maintenance, Steering) with technical/customer descriptions, flat-rate labor hours, required parts, companion/upsell jobs, and VIN-aware adjustments. Collections: `estimate_job_knowledge_base`, `estimate_audits`.
    *   **Smart Job Builder API** (`/api/estimate-assist/job-builder`): POST endpoint that accepts a job name/ID + optional VIN, returns structured estimate line with labor hours (KB + shop historical average), parts list, companion/upsell jobs, VIN-specific adjustments, and AI enhancement for unknown jobs.
    *   **AI Estimate Language API** (`/api/estimate-assist/language`): POST endpoint that converts estimate text between technical and customer-facing language, with line item completeness validation.
    *   **Estimate Audit Engine** (`/api/estimate-assist/audit`): POST endpoint that accepts a work order ID or array of line items, runs rule-based analysis (missing parts/labor, labor hour anomalies, missing companion services) + AI analysis, returns findings with severity (critical/warning/info), confidence scores, and overall score. Audit history saved to MongoDB.
    *   **Audit History API** (`/api/estimate-assist/audit/history`): GET endpoint with `startDate`, `endDate`, `severity`, `limit`, and `offset` query params. Returns paginated audit history with findings for the current shop.
    *   **Audit Dashboard** (`/dashboard/estimate-audit`): Client-side page with Estimate Audit, Smart Job Builder, and Audit History tabs. Audit History tab supports date-range and severity filtering with expandable audit details. Findings link through to the Job Builder.
    *   **Extension Integration**: Detect Dog Chrome extension "Estimate" tab with Job Builder sub-tab (search, language toggle, VIN-aware results, "Send to RO" button via `handleAddJob`) and Audit RO sub-tab (one-click audit of current repair order with inline findings and "Add to RO" buttons for suggested jobs).
*   **Work Order Creation**: A multi-step wizard facilitates creating Protractor work orders from the dashboard, integrating AI assistance and VIN/license plate recognition.
*   **Vehicle Health Report (VHR)**: A shareable, mobile-friendly customer-facing report page displays a health score, overdue items, and a service timeline.
*   **VHI API Endpoints & On-Demand Analysis**: Both internal and external API endpoints provide Vehicle Health Indicator data, including a health score and bucketed maintenance items. On-demand analysis allows real-time VHI generation.
*   **Partner API Keys**: Global API keys facilitate shop resolution per-request and broader access for integration partners.
*   **VHI Auto-Build & Rebuild**: VHI data is automatically built and rebuilt when work orders are created and closed.
*   **Swagger UI**: Interactive API documentation is available at `/docs` and `/api/docs/ui`.
*   **Common Maintenance Layer**: Industry-standard maintenance items are automatically integrated into plans when not covered by OEM data, respecting shop-specific overrides.
*   **Service Key Matching** (`lib/service-keys.ts`): Shared module for normalizing free-text service job names from shop management systems to canonical service keys (e.g., `oil`, `spark_plugs`, `brake_fluid`). Used by VHI plan-build, extension plan, and diagnostics. Contains ~200+ keyword phrases across 27 service categories covering common SMS naming patterns including R&R/R/R, brand names, and shorthand.
*   **VHI Plan Diagnostics** (`/api/plan-build/diagnostics`): Platform-admin-only GET endpoint for debugging VHI issues per vehicle. Returns raw service history, matched/unmatched job names, last-done-by-service-key, active shop interval overrides, cached plan state, and interval apply mode. Query params: `vin`, `shopId`.
*   **Interval Apply Mode**: Default changed to `"always"` — when shops configure custom intervals, they apply to all vehicles regardless of where the last service was performed. Shops can still explicitly set `"shop_only"` if they prefer OEM intervals for vehicles last serviced elsewhere.
*   **Communications**: Twilio powers voice calling, SMS, voicemail recording, and caller ID lookup, with conversation tracking.
*   **Rescue Rover AI Voice Agent**: An AI-powered SaaS client support phone assistant using Twilio media streams, Deepgram for STT/TTS (with automotive keyword boosting), and OpenAI GPT-4o for conversational intelligence. Callers are shop owners/managers (not vehicle owners). Features include: client account lookup (billing, integrations, features, ticket history), support ticket creation directly from calls, integration status checking, barge-in detection (caller can interrupt AI), post-call AI summary generation via GPT-4o-mini, silence detection with caller prompting, transfer to MOS support team, and comprehensive call logging with cost tracking.
*   **Call Center Management**: Features include phone number management, agent groups with performance targets, time tracking, a call activity dashboard, and canned message templates.
*   **CRM Account Hierarchy**: A multi-tier CRM account hierarchy supports Agencies, Parent Organizations, Accounts, and Locations, with configurable RBAC roles and corporate branding overrides.
*   **CRM Contact Management**: A full contact management system tracks business contacts across the account hierarchy, supporting CRUD operations, search, and polymorphic entity notes/tasks.
*   **CRM Sales Pipeline & Marketing Engine**: Includes a Kanban-style deal board, configurable funnel stages, campaigns management, coupons, specials, message templates, and comprehensive pricing administration.
*   **CRM Onboarding & Content System**: Provides a Trello-style onboarding board with configurable stages and steps, tours, guides, banners, and content assignment to user types.
*   **Normalized Data Schema (Supabase)**: Six Drizzle ORM tables in Supabase PostgreSQL mirror core normalized MongoDB collections for vehicles, customers, work orders, service jobs, line items, and payments, including JSONB columns for nested objects and comprehensive indexing. DataOne VIN reference and maintenance data also lives in Supabase PostgreSQL (accessed via `DATAONE_DATABASE_URL || DATABASE_URL`).
*   **Normalized Data Dual-Write to Supabase**: The `NormalizedIngestionService` performs dual-writes to both MongoDB and Supabase/PostgreSQL for core normalized entity types. Supabase write failures are logged but do not block MongoDB writes.
*   **Job Search Triple-Source**: Job search queries three sources in parallel: (1) MongoDB `job_index` (legacy flat collection), (2) MongoDB `normalized_service_jobs` (via aggregation + lookup), (3) Supabase PostgreSQL `normalized_service_jobs` (via Drizzle ORM join with `normalized_work_orders`). Results are deduplicated across sources and scored using DataOne-powered vehicle specs (GVWR class band, body type, drive type, displacement) resolved via batch squish lookup against `dataone_vin_reference`. Key files: `lib/job-scoring.ts`, `lib/supabase-job-search.ts`, `lib/normalized-job-search.ts`.
*   **Support Tickets Dual-Write**: Support tickets are written to both MongoDB (`support_tickets` collection) and Supabase PostgreSQL (`support_tickets` table). Both the web API route and Rescue Rover call-created tickets perform dual-writes. Supabase failures are non-blocking.
*   **Production Log Caching**: Production logs from Better Stack (ClickHouse) are synced to a Supabase `production_logs` table with 30-day retention. A cron endpoint (`/api/cron/log-sync`) fetches recent logs in batches and deduplicates via content hash. The `/platform-admin/logs` page reads from Supabase for fast, filterable access with search, level filtering, and time ranges up to 30 days. Platform admin auth required.
