The driver problem on ARM64 is real
Traditional printer drivers are compiled native code. On ARM64 Windows (Surface Pro X, Surface Pro 11, etc.), x86/x64 drivers either don't work at all or run under emulation with reliability issues. This is a known pain point — many older printer drivers simply don't have ARM64 builds. If you were going the driver route, this would be a serious problem.
The TCP/WiFi approach sidesteps this entirely
Since you're just opening a TCP socket to port 9100 on the printer's IP address, there's no architecture-specific native code involved in the printer communication itself. A TCP socket is a TCP socket regardless of whether the CPU is ARM64, x86, or anything else.
The only ARM64 consideration is your companion app
