#302 - Remove Plaintext Password Fallback in Extension Auth
What & Why
app/api/extension/auth/route.ts:67 still has a legacyPlain path that compares the submitted password against a plaintext value stored in the database, then opportunistically rehashes it to bcrypt on success. This is a real security debt — any unhashed user record in the DB is exposed to anyone with read access — and it's a DB-switch landmine because the column shape carries the legacy data alongside the hashed data. Before we make Supabase canonical we want every credential row in a single, hashed shape.

Done looks like
An audit identifies how many user rows still have plaintext credentials and which shops they belong to.
A one-time backfill rehashes any remaining plaintext credentials. (If the row truly has no recoverable hash, the user is forced through password reset on next login instead of silent rehash.)
The legacyPlain branch is deleted from app/api/extension/auth/route.ts. Auth becomes bcrypt-only.
A test asserts that a user row with no bcrypt hash returns 401 (not 200 with a silent rehash).
A test asserts that a user row with a bcrypt hash and a correct password returns 200, and an incorrect password returns 401.
The same audit is run against the regular app/api/auth/login/route.ts to confirm no equivalent legacy path exists there; if it does, it's removed too.
Out of scope
Password reset UX changes beyond what's needed to handle the "no recoverable hash" case.
2FA, session rotation, or other auth hardening.
Steps
Audit — Query for user rows where the password column does not look like a bcrypt hash. Record counts per shop.
Rehash where possible — For rows where the plaintext is still present, run a one-time script that rehashes and clears the plaintext column.
Force-reset the rest — For rows with neither a usable plaintext nor a bcrypt hash, mark them as requiring reset and notify the affected shops out-of-band.
Delete the legacy branch — Remove the legacyPlain path from the extension auth route. Audit app/api/auth/login/route.ts and remove any equivalent.
Add the tests — Two unit tests on the auth route covering the cases above.
