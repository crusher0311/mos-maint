The shared workflow/DVI boundary initially covered dark contracts only. The user
subsequently approved implementing persisted manual staff inspections in Shop
Workflow independently of provider concurrency certification. The user then
approved findings-only customer-release implementation after offline staff
verification, without waiting for native provider-safety certification.
Those earlier implementation approvals did not include live activation, named-shop
provisioning, production database operations, or enabling release/provider gates.
Existing enterprise/customer match proposals retain ownership of discovery.

**Why:** The user separates implementation of the local customer release milestone
from operator activation and from native Protractor writes.

**How to apply:** Staff persistence and its authenticated entry point are approved
implementation scope. Obtain separate approval before live provisioning or
activation. Do not interpret offline success as permission to
activate live reports, migrate legacy VIN records or implement another enterprise
matching feature. Review the additive storage proposal and unsettled
two-store reconciliation boundary before connecting real stores.

The user subsequently authorized a CAR Experts Protractor testing pilot with
explicit provider writes, accepted the documented unresolved provider test risks,
and clarified: "It shouldn't be restrictive to a singular RO, I want to be able
to test the whole check in process".

**Why:** A single pre-existing fixture cannot exercise check-in and creation of
new test visits. A local-only inspection pilot does not meet the stated goal.

**How to apply:** Prepare full check-in through native inspection write-back for
synthetic CAR Experts Protractor visits, not only the original synthetic order.
Do not interpret accepted test risks as verified provider guarantees or approval
for other shops, existing customer orders, customer publication, or automatic
replay of ambiguous writes. Record the pilot exception separately from provider
certification; obtain missing sheet, retention and rollback-owner decisions.

The user approved Manual vehicle inspection v1, retention of synthetic test
evidence/photos/receipts until separately approved cleanup, and personally owns
stopping the pilot.

**Why:** These are explicit pilot configuration decisions, not defaults inferred
from a candidate template or from the provider test-risk exception.

**How to apply:** Reuse this approval for the scoped CAR Experts synthetic pilot.
Do not broaden it to customer publication, real customer records, other shops,
automatic deletion, or provider safety certification.

The user approved separating the tested implementation handoff from live pilot
activation.

**Why:** The isolated implementation workspace cannot release the changes into
the serving app; a merge-ready implementation is not an enabled pilot.

**How to apply:** Keep activation and real native readback as separate operator
work after the serving build is verified. Do not report offline fixture results
as evidence of live activation.
